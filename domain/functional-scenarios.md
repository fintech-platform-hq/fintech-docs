# MF01.1 decisions and scenario fixtures

The owner approved A01–A12 on 2026-11-24. MF03.1 refines their observable behavior. The figures below are synthetic BRL examples. See [the domain model](functional-model.md), [behavior](behavior.md) and [traceability](functional-traceability.md).

| Decision | Approved rule and example or counterexample |
| --- | --- |
| A01 · Deletion · CA01 | Reauthenticate and confirm. Acceptance sets the write barrier. Track original rejection, progress, partial failure or completion with protected lookup after session invalidation. A write committed first enters deletion scope, a write losing admission cannot commit afterward. Resolve relevant Apple revocation and data disposal with narrowly justified retention. |
| A02 · Identity · CA02 | Use stable holder identity. Verified email gates password reads and writes. Apple can authorize the same hybrid holder while password verification is pending. Matching email confers no link. Linking needs consent and both proofs. Competing voluntary removals leave at least one usable method. External revocation can leave none. |
| A03 · Legacy · CA03 | Preserve records and authorized history before baseline, with calculated figures unavailable. Require ownership, integrity and writer compatibility before adoption. The S06 approved fixture is conditional. |
| A04 · Matching · CA04 | Require human confirmation and identifiable evidence. An eligible existing expense linked to a calculable open discrepancy has zero monetary effect. At a numerical match require nonzero original and demonstrated contribution, for example an expense entered later whose occurrence falls before cutoff. Correct or restore the same pair with separate decisions, keeping record, evidence and transaction. Distinguish compatible replay, conflicting reference and deliberate reuse. |
| A05 · Reopening · CA05 | Require prior attributed resolution of the same check. Use the last applicable proved zero episode and distinct messaging for a numerical match. An unavailable interval can preserve a proved trajectory. Without proof, show current classification. |
| A06 · Time · CA06 | Editable current instant, day-only precision when all relevant predicates agree, exact boundaries and zone. Defer or ask for precision at ambiguity, including repeated or nonexistent times. Neither the beginning nor end of a day implies an exact occurrence time. |
| A07 · Money · CA07 | Exact BRL cents. Transaction range is 1–999,999,999 cents. Opening and reported balances have independent signed Int64 ranges and explicit zero. Aggregates and differences remain exact beyond that range. Unavailable differs from zero. |
| A08 · Intents · CA08 | Keep original protected through eligible sign-out, scoped to holder, environment and target. Lookup is read-only and resubmission deliberate. Only definitive rejection without effect permits an edited replacement. Local loss proves no outcome. No cross-device synchronization in MVP. |
| A09 · Distribution · CA09 | Controlled activation only after app/API/schema compatibility, security, data integrity, quality and operational checks. Temporary flags require reasons and removal criteria. Debug opt-in is historical implementation evidence. Release requires its own acceptance. |
| A10 · History · CA10 | Search the full authorized set by description. Combine type and civil-day period in the account zone, inclusive start and exclusive next-day end. Use stable ordering and compatible paginated revisions. On restart preserve filters. |
| A11 · Terminology · CA11 | Use the canonical bilingual glossary, retain approved UX01 names and review candidate labels separately for comprehension and accessibility. Technical identifiers retain their source meanings. |
| A12 · Replacement · CA12 | Erroneous amount and/or cutoff requires reason, preview, current revision and new identity with its own original. An independent real observation may use the same cutoff. Preserve predecessor links and both edge reasons at an intermediate check. Deliberate evidence reuse requires a new eligible association without creating another transaction. |

| Fixture | Expected outcomes |

| S03 · Recover, reopen and replace | Bakery expense 25 yields current 802, cutoff 820 and +20 partially explained. Expense 20 yields current 782 and attributed zero. Correct bakery to 24 for current 783 and +1 reopened, retaining original 845/800/+45. Independent 11:00 check reporting 783 is a numerical match. | S04 · Reverse, move, invalidate | On S02, retroactive 50 gives −5 open. On resolved S03, move bakery after cutoff for current 782 and +25. Separately invalidate expense 20 for current 802 and +20. |
| S05 · Matching | Zero, one and many candidates all require review. Deferring preserves state. Link preserves balance and remaining difference. Already counted unchanged expense contributes zero. Distinct 25 from +20 gives −5. Compatible recovery can find the existing result. Incompatible target or terms require review. Deliberate reuse keeps the expense and adds only an eligible new pair. Withdraw attribution without changing balance or remaining difference. A stale preview needs refresh even without an external reference. |
| S06 · Legacy and opening | Independently: (1) old owned expenses 55 and 18 are readable before baseline, preserving IDs with no figure. (2) Concurrent new opening yields one account/baseline, and replay obtains its receipt. (3) Conditional adoption declares 845 just before 2026-11-18 08:00 −03:00. Keep the 55 from November 14 as pre-coverage and count coffee 18 at 09:00 for 827. A different fixture's T0 would give 772 and is inapplicable. The approved adoption fixture includes lost response and commitment races. |
| S07 · Timeout by target | Pre-commit failure and post-commit reply loss converge under explicit resubmission of original to one coffee, one ID, one receipt and current 827. An edited body with the same key conflicts. Initial and later lookup perform zero writes. Run before/after-commit examples across opening, adoption, creation, correction, invalidation, refinement, check, replacement, existing link, recovery expense, link correction, restoration, suspension and baseline correction. |
| S08 · Restart and identity isolation | Restart before network and after possible commitment preserves protected body and key if intact. Scoped A can resume after expiry and sign-out with fresh authority. B, another environment or target and an expired session cannot reveal data or transmit. Failed protection before network allows repair. Local loss or another device retains uncertainty and blocks equivalent writes without proof. |
| S09 · Concurrent writes | Shared revision. Correction 25→24 wins with 783/+1. Correction 25→23 and a new check with old revision require review. Compatible replay returns the winner despite stale preview. Failure before link or receipt preserves whole prior revision. |
| S10 · Suspend and correct baseline | Suspension removes affected derived amounts and preserves originals. Correct 900→910 at same T0 for 837 current, 855 recalculated, +55 remaining and +45 original. A zero original remains zero during unavailability. T0 changes alone generate no attribution. |
| S11 · Time precision | Unambiguous retroactive 10 on November 15 gives +35. November 14 straddles T0 and November 18 straddles cutoff. Ask for precision or defer. Refinement preserves the fact. Exact new T0 is included, earlier cutoff unavailable. Coverage reclassification contributes no recovery credit. |
